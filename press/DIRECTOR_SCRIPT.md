# 拍簿 — 影片素材導演腳本

> **這份檔案是所有影片／動態素材的唯一需求來源。**
> 要改任何一段演示，**先改這裡**，再照著改實作。
> 這樣才不會在新一輪修改中，不小心把舊版本要求過的細節弄丟。
>
> 涵蓋三個產出：
> - **商店預覽影片＋投放廣告**（v2，2026-10-03 起；Remotion，`site/press/remotion/`，輸出到 `store_assets/videos/`）
> - **官網首頁的實錄示範影片**（`site/assets/shots/*_demo.mp4`，§5）
> - **App Store 創意素材影片**（iOS 27 起的產品頁標題／搜尋結果；`site/press/creative/`，輸出到 `store_assets/creative/`，§8）

## 0. 不可退讓的前提（每次重錄都要重新確認）

| # | 規則 | 為什麼 |
|---|---|---|
| P1 | 素材一律是**實機真實操作錄影**，不是模板重刻、不是靜態圖加緩慢放大 | 商店預覽的說服力全部來自「這真的是 App 的樣子」。投影片式的 Ken Burns 一眼就看得出是拼湊的 |
| P2 | 打包必須是**正式商店狀態**：`dart_defines.store.json`（**不含** `PIBOOK_DEV_TOOLS`） | 帶開發者旗標時相似組標題會多一顆實驗 icon（複製相似報告），使用者已回報過 |
| P3 | 示範用的照片／影片必須是**一般人真的會拍的東西**：人像、多人聚會、狗貓、表演、煙火、食物、風景 | 樣板圖庫感會讓人覺得是假的 |
| P4 | **素材不得有裸露**（泳裝、裸上身一律不用） | 商店審查與品牌調性 |
| P5 | 錄影前先確認**資料狀態符合演示情境**：要示範「加入相簿」，被示範的照片就必須還沒被加入過任何相簿 | 使用者回報過「有些照片你稍早已經示範加入過了」 |
| P6 | 不同尺寸**各自渲染一次**，禁止「渲染一支再裁另一支」 | 長寬比 0.461 vs 0.5625，裁出來一定切掉上下一大塊 |
| P7 | 回憶頁的示範影片一律 **1080p／真 30fps／6 Mbps 輕量版**（`video/dedup_video.py`） | 模擬器的瓶頸是影片解碼；而且有些片源是 24fps 做 pulldown 或 25fps，放進 30fps 成片每 5–6 格就重複一格 |
| P8 | **錄影素材一格都不准掉**：一律用慢動作錄影包錄（§3），每段錄完跑 `rec.check` 與 `rec.flashes`，兩個都是 0 才收 | 模擬器每秒只畫得出約 20–24 張畫面，舊版素材的「卡卡的」就是這個 |
| P9 | 素材**不含任何系統列**（狀態列、手勢列都裁掉） | 與 2026-09-23 起的商店截圖同一規格：兩個商店共用一份，不會再因「非 iOS 狀態列」被以 2.3.10 退件 |

### 1.1 整體風格

- **先講痛點、再一段一個功能**：開場一小節（2.4 秒）講痛點，之後每段 2.4–3.6 秒只講一件事。
- ⭐ **說明文字跟著操作走，不放在畫面頂端**（2026-10-03 使用者第二輪指正：「說明在最頂部，眼睛沒辦法同時看說明
  又注意底下的操作；節奏快、字又沒有很精簡，根本沒時間讀」）：
  - 頂部只留一行小小的品牌字標（App 圖示＋拍簿 PIBOOK），手機放大（高 1524/1920）。
  - 說明改成**字卡**，在手指動作前一刻浮出。⭐ **位置永遠固定**（第三輪裁示：「節奏很快，觀眾習慣注視字幕
    出現的位置，一下上一下下會來不及看」）。v2.2 放在手機正下方的字幕帶；**v3 改成手機畫面上中下方**（V1）。
  - 一張字卡 **8 個字以內**，「動作　結果」的句型（左滑　保留／點相簿　就歸檔），動作那兩個字上色。
  - 奶油底用深色卡、夜色底（回憶）用米白卡；純色、不發光。
  - 開場沒有操作要看，痛點大字直接壓在手機畫面正中央（暗幕＋白字）。
  - 播放速率壓在 1.3 倍以內（v2 的修圖段 1.75 倍太快，看不懂在做什麼）。
- 手機外框與截圖同一支（`site/assets/phone.css`：深色邊框、不畫瀏海、不畫系統列）。
- 克制：純色底＋截圖畫板那層極淡的品牌光暈；回憶與結尾用夜色底。
- 每次切段手機輕彈一下（0.982 → 1）；**每一次切換都落在配樂的拍點上**（§1.5）。
- 規格：30fps、H.264、AAC 音軌（App Store 規定一定要有）。

### 1.2 三條鏡頭語言的鐵則（v1 沿用）

| # | 規則 | 為什麼 |
|---|---|---|
| C1 | **切到一段實機畫面後，動作必須在 ~0.3 秒內開始。** | 停太久使用者 get 不到這一幕要傳達什麼 |
| C2 | **要介紹的細節必須主動聚焦。** 推近／局部高亮把視線帶到目標上（圖庫縮圖上的記號＋文字標籤） | 只是把整個畫面播出來，使用者不知道該看哪裡 |
| C3 | **不要用「整段緩慢放大」當運鏡。** 外框不動、動的是內層；運鏡是「停 → 一次彈簧推近 → 停」 | 連續次像素縮放會讓邊緣抖動閃爍（使用者回報過） |

> 橫跨全寬的東西（相簿軌、結尾頁的成果列）**不推近**：寬度一放大兩端就被裁掉。交給觸控指示圈帶視線。

### 1.5 配樂與音效

- **原創配樂**，`video/music.py` 照 `timeline.json` 直接合成（完全自有、沒有授權問題）。
- 音色跟 App 的操作音效同一台「紙與木」（`tool/gen_sfx.dart`）：木琴主音色、溫暖和弦墊、輕的大鼓／拍手／沙鈴、
  後半段加一條鐘琴旋律。C 大調，App 的音效（C 大調五聲音階）疊上去永遠不會不協和。
- 100 BPM，一拍 0.6 秒、一小節 2.4 秒：開場剛好一小節（只有和弦墊與往上爬的木琴，「懸著」），
  第一個功能出現的那一拍進鼓；每段功能都是整數拍，中間功能段加總是整數小節 —— **畫面切換永遠在拍點上**。
  結尾卡停鼓，木琴琶音落在 C 大三和弦上收掉。
- **操作音效**用 App 自己的音檔（`assets/sfx`），放在手勢生效的那一刻：左滑保留 `keep`、下滑丟棄 `discard`、
  點相簿 `file_away`、雙擊 `favorite`、其餘點擊 `tap`。跟配樂一起在 Python 混好、統一限幅（峰值 −1 dBFS 以下），
  Remotion 只放一軌。
- 響度：主段 RMS 約 −17 dBFS。手機喇叭放不出的超低頻（< 45Hz）濾掉，否則正規化時算進去、聽到的反而變小聲。
- 想換成授權音樂：把 `remotion/public/music/<版本>.wav` 換掉即可（操作音效要另外混）。

## 3. 慢動作錄影（2026-10-03 起的唯一錄法）

### 為什麼

模擬器上 App 每秒只畫得出約 20–24 張不同的畫面（實測：主機端錄 60fps，四成是重複格）。
瓶頸在模擬器的 CPU，換錄影工具、調參數都追不回來 —— v1 素材「卡卡的」就是這個。

所以錄影包帶 `--dart-define=PIBOOK_CAPTURE_DILATION=4`（`lib/core/config/capture_time_dilation.dart`）：
動畫（`timeDilation`）、**手勢速度**（指標事件時間戳一起除以 k，否則放手後卡片飛得比手指慢）、
影片播放速度、常駐動畫的共用時鐘，全部一起慢 k 倍；手勢腳本也照 k 倍慢做；錄完把時間軸壓回 1/k。
每秒 24 張 × 8 ＝ 每秒 190 張真畫面，取 30fps 時每一格都是 App 真的畫出來的，不補幀、不模糊。
**正式包完全不受影響**（編譯期常數，分支被 tree-shake 掉）。

### 倍率怎麼選（實測）

| 倍率 | 用在 | 原因 |
|---|---|---|
| 8（預設） | 幾乎全部 | 4 倍吸收不掉模擬器偶發 0.13–0.27 秒的停頓（滑卡判定那一刻會停一格） |
| 24 | 圖庫（點開瀏覽、開始整理）、相似照片（打開全螢幕比對，另加暖機） | 那幾個瞬間在模擬器上會停 0.3–0.5 秒；主機上同時有另一台模擬器在跑時停得更久 |
| ⚠️ 影片播放 | 回憶 | 播放器遇到延遲時會丟掉遲到的影格，跟倍率無關；8 倍最穩。另外**主機錄影開 60fps 時編碼器自己會漏格** → 錄影一律 24fps |

倍率在錄影包裡可以不重新打包就換：`rec.set_dilation()` 會把 `PB_K` 寫進
`/data/data/com.minobear.pibook/files/capture_dilation`，App 啟動時讀。

### 會踩的坑

- **慢動作下長按的判定是真實時間 0.5 秒** → 拖得太慢時，手指還沒移出觸控門檻（47px）就被當成長按。
  拖曳要讓手指在 0.3 秒（真實時間）內移出 47px。
- **雙擊的判定窗也是真實時間**（0.3 秒）→ 兩下之間不能放慢（`rec.double_tap`）。
- Timer／Future.delayed 的等待不會放慢（吐司停留、自動換下一張的延遲）→ 成片裡變成 1/k 長，看起來是「更俐落」。
- 第一次開修圖（shader 編譯）、第一次開分享面板會多停一下 → 同一個行程裡先開一次再關（`shoot.py` 的暖機）。
- 回憶頁第二支影片會跳「附近」的引導氣泡 → 錄前先滑兩次、關掉。
- 原生影片元件開始移動的那一格偶爾會**整片閃黑** → `rec.flashes()` 抓得到；重錄挑乾淨的那一次，
  或 `rec.fix_flashes(name)` 把那一格換成前一格（`m_memory` 的 1.43／4.77 秒兩格 2026-10-06 這樣修掉）。
- 偶爾還是會掉一格（「動、停、動」）→ 整條橫向捲動的東西（壓縮成果頁的前後對比列）用
  `rec.fill_scroll_drop(name, 格號, (y0, y1), 位移)` 把前一格那條帶子平移半步補上。
  ⛔ 不要用 ffmpeg `minterpolate` 補：重複紋理的捲動列它會配錯對應點，補出來那一格整條糊掉（`r6_done` 試過）。
- 段落之間是剪接：**段落起點之前就按下去的手勢不畫**（`Phone.tsx` 過濾 `tc.b < from`）。
  否則上一刀的觸控圈會拖進下一刀 —— `similar_done` 開頭殘留的圈剛好落在成果頁的「完成」上，像在按完成。

| 想改的 | 成本 | 怎麼改 |

## 6. v1（2026-08-31〜09-04）留下的經驗

v1 的分鏡（滿版標題卡＋六段、長短兩版）已被 v2 取代，程式碼與素材已移除；下面幾條仍然成立。

## 8. App Store 創意素材影片（產品頁標題／搜尋結果，2026-10-06）

跟預覽影片是兩回事：預覽影片示範操作（Apple 2.3.4，一定要實機錄影）；創意素材是**品牌主視覺**，
Apple 允許「不是 App 實際使用畫面」的內容。所以這裡不錄影，畫面就是靜態主視覺動起來。

第一版（左邊整理好的圖庫、右邊亂丟的照片、中間一疊卡被左滑保留）被使用者否決：比喻沒人看得懂、
影片只有滑卡保留、跟商店裡其他滑卡整理 App 沒有分別，「不管什麼尺寸都要看得到相簿軌」。第二版：

| # | 要求 | 為什麼 |
|---|---|---|
